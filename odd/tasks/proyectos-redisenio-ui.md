Objective: implement the PO-approved redesign of the project ficha (Resumen, Actividades, Finanzas, Documentos, Historial), desktop and mobile.
Branch: `feat/proyectos-redisenio-ui` (worktree `.claude/worktrees/redisenio`, base `origin/main@0726e5d`). Delivery: work-unit commits on this branch; PR split decided by the human.

- **S7 — Constraints.** UI-only in this pass: no schema/API contract changes; behaviour that needs the API is listed as follow-up. Open PO questions (`docs/ux-crm-2026-11/reporte-sesion-2026-11-05.md` §6) keep today's behaviour — notably validating a gasto over its rubro stays blocked. Do not touch `proyectos-v3` or its flag; only `.env.local`; Vitest/Next only with `node.exe` and `--dir src`.
- **S8 — Gastos por validar: the Acción cell is never empty.** User (2026-11-06): «Lo que podemos hacer es que se muestre el icono, pero si no tiene el rol y los permisos necesarios que le aparezca un popup que no tiene los permisos necesarios». The prototype (`prototipo-ficha/tabs/finanzas.js:65-71`) shows «Ver» there instead. Keep «Revisar» for a manager on someone else's expense and «Tú lo registraste» on one's own. Assumption to confirm before coding: the popup copy is one sentence saying the user lacks the permissions to validate expenses, and the same rule applies to the phone card and to the `AccionesGasto` cell of the full Gastos table (`project-gastos.tsx:270`).
- **S9 — Semáforo chip in the header.** User (2026-11-06), message cut off: «el botón … Semáforo técnico: Rojo … abrí un modal donde me dejaba seleccionar la actividad y colocarle los datos. Open: the user has to restate what they want from the chip before T9 is coded.
