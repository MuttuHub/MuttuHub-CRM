## 2. Template layout (PLANTILLA_VERSION "2026.1", §8.2 confirmed against models)

Files: `src/lib/proyectos/plantilla/columns.ts` (constants) + `generate.ts`. Sheet names exact, in order:

1. `1. Instrucciones`: A1 title, `B2 = PLANTILLA_VERSION`, A4.. usage text (codes unique, `;` lists, weeks 1..N, Colombian numbers OK). Not imported except B2.
2. `2. Proyecto` (`Campo`,`Valor`): rows 2..9 fixed labels: `Código` (prefilled, locked), `Cliente` (prefilled, informative), `Líneas estratégicas`, `Municipios`, `Fecha de inicio`, `Fecha de fin`, `Valor total`, `Meta de beneficiarios`. Parser finds rows by LABEL in column A (not by row index) so inserted rows do not break it.
3. `3. Objetivos`: `Código`,`Descripción`. 4. `4. Actividades`: `Código`,`Código objetivo`,`Nombre`,`Semana inicio`,`Semana fin`,`Responsable (correo)`,`Peso (opcional)`. 5. `5. Entregables`: `Código`,`Código actividad`,`Descripción`,`Cantidad`,`Unidad`,`Tipo de medio exigido`. 6. `6. Indicadores`: `Código`,`Código objetivo`,`Nombre`,`Meta`,`Unidad`,`Línea base`.
7. `7. Presupuesto`: `Código rubro`,`Rubro`,`Valor asignado`; 15 precargadas rows from `RUBROS_V2` (active DB rubros with code, ordered by `orden`), `Valor asignado` prefilled with the CURRENT `lineas_presupuestales` amount (0 if none).
8. `8. Programación`: `Código rubro`,`Rubro`,`Mes 1 (AAAA-MM)`..`Mes N (AAAA-MM)`,`Total`,`Control`; N = `projectPeriods(inicio, fin).length` (monthly, DP-12); cells prefilled with current `programacion_periodo`; `Total = SUM(C:..)`, `Control = Total - VLOOKUP(rubro, '7. Presupuesto'!A:C,3,FALSE)` written as `{formula, result}`.
9. `9. Catálogos`: `Rubros` (`R01 - Personal`? no: code only), `Líneas estratégicas`, `Municipios`, `Unidades`; protected with a random per-download password never stored; named ranges `Rubros`, `Lineas`, `Municipios`, `Unidades` (`workbook.definedNames`). `sheetState` "visible" but protected (SDD says protected, not hidden; hidden is a cosmetic option).
Validations: `7./8.` `Código rubro` list `=Rubros`; `4.` `Código objetivo` list = range of `3.` column A (`='3. Objetivos'!$A$2:$A$200`), `5.` `Código actividad` likewise on `4.`, `6.` `Código objetivo` on `3.`; `2.` Líneas/Municipios are `;`-lists so NO list validation on them (a list DV forbids multi-values): show the allowed values in `9.` and a cell note. Decimal DVs: `Cantidad`/`Meta` > 0, `Semana *` whole >= 1, `Valor asignado` decimal >= 0.
Matching keys for `2. Proyecto` lists (decision): líneas by catalog `codigo` (token before ` - `, accept bare `LE03` or `LE03 - Productividad`, case-insensitive; fall back to exact `nombre`); municipios by `Nombre (Departamento)` or `codigo_dane` (names repeat across departments, so bare name matches only when unique). `9. Catálogos` lists the canonical strings that the parser accepts.

## 4. API routes

- **E-23 `GET /api/v1/projects/:id/template`** (`route.ts`, `force-dynamic`): 404 -> 403 (`canManageProjects`) -> 409 INVALID_STATE if not BORRADOR -> 409 if `fecha_inicio`/`fecha_fin` null ("Define las fechas del proyecto antes de descargar la plantilla.", same as programming GET). Loads project (codigo, cliente.nombre, dates, valor_total, beneficiarios_meta, lineas, municipios, live objetivos/actividades/entregables/indicadores, lineas_presupuestales, programacion) and catalogs; returns `new Response(buffer, {Content-Type: xlsx, Content-Disposition: attachment; filename="<codigo>-plantilla.xlsx"})`. Prefill with current data so download -> edit -> import is the edit loop. Audit `EXPORTAR` (best-effort, `logAudit`, like clients/export) is optional (decision D-4).
- **E-24 `POST /api/v1/projects/:id/import`**: multipart `archivo` (field name per SDD E-24; the existing upload routes use `file`: accept `archivo`, fall back to `file`) + optional field `modo=validar` (dry run; ALSO accepted as `?dry_run=1`). Order: 404 -> 403 -> 409 -> `formData()` 400 -> extension `.xlsx` + MIME check (`isAllowedNameAndMime`, xlsx only) 400 -> size 413 -> zip pre-check (JSZip central directory: reject if total uncompressed > 50 MB or > 200 entries, 400 "El archivo no es una plantilla válida") -> parse -> validate -> write.
  - Dry run 200: `{ importado:false, valido:true, resumen:{objetivos,actividades,entregables,indicadores,rubros,celdas_programacion}, reemplaza:{objetivos,actividades,entregables,indicadores}, advertencias }` or 400 with the report; never writes, no audit.
  - Apply 200: `{ importado:true, lote_id, resumen, advertencias }`.
  - Failure 400: `{ error, code:"VALIDATION_ERROR", reporte:{ errores:[{regla,hoja,fila,columna,valor,mensaje}], advertencias:[], resumen:{"V-07":1}, truncado:false } }`. NOTE: check `apiError` envelope in `src/lib/api/errors.ts` before fixing the shape (extra `reporte` key needs a small `apiError` extension or a direct `NextResponse.json(..., {status:400})`).
  - Concurrency: inside the transaction call `lockProyectoBorrador(tx, id)` (row lock + BORRADOR recheck) so a baseline approval cannot interleave; map `RespuestaAbortada` like budget PUT. Transaction options `{ timeout: 60_000, maxWait: 10_000 }`.
- OpenAPI: `src/lib/openapi/paths/project-template.ts` registered like `project-budget.ts` (the repo tests that every route is documented; run the OpenAPI test).
- A `COORDINADOR` (even a member/responsable) gets 403: import changes budget and value, manager-only (matrix P06).
